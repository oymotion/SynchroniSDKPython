2.2 支持的设备类型清单（多设备）

SDK 支持多设备并存，且同一次扫描/连接/起流可操作多台。由于本仓库未提供具体设备型号清单，以下按可观测的区分维度列出“设备类型”，每类都需要纳入计划：

A. 按连接/协议/命名区分

设备类型 识别特征 备注
OYM 命名设备 广播名前缀 OY（如 OYWW1000） 传统 OYMotion 设备
OB 命名设备 广播名前缀 OB（如 OB6000） 多设备同步测试的典型目标设备
Sync 命名设备 广播名前缀 Sync console.py 中与 OB 并列过滤
RFSTAR 芯片设备 bin 配置 chip_type=RFSTAR；起流/停流走 set_subscription 命令 与 OYM 的 CCCD 写路径不同
NeuCir 设备 支持 NEUCIR_SET_MODE/NEUCIR_APP_CONTROL 参数 远程控制类设备

B. 按数据模态/能力区分（由 DeviceInfo.*ChannelCount/*SampleRate 决定）

设备类型 关键能力字段 / 数据流 备注
传统 EMG 设备 Emg*，NTF_EMG NTF_GEST 与 NTF_EMG 互斥
新 EMG 设备 Emg*，NTF_IMU（聚合 acc/gyro/euler/quat）+ NTF_GEST lostPackageCount 非 0 仅新 EMG 设备
EEG 设备 Eeg*，NTF_EEG 支持 EEG_SAMPLE_RATE
ECG 设备 Ecg*，NTF_ECG 与 EEG 采样率绑定
呼吸 BRTH 设备 Brth*，NTF_BRTH 单位 uV
PPG/SpO2 设备 Ppg*/Spo2*，NTF_PPG + NTF_SPO2 常含 EEG fp1/fp2
IMU 设备 Acc*/Gyro*/Euler*/Quat*，NTF_ACC/GYRO/EULER/QUAT 传统四路独立流
磁角度 MagAngle 设备 MagAngle*，NTF_MAG_ANGLE_DATA —
阻抗 Impedance 设备 Impe*，NTF_IMPEDANCE / NTF_IMPEDANCE_EXT —

上述两类维度是正交的：同一物理设备可能同时属于“OB 命名” + “新 EMG 设备” + “IMU 设备”。计划中“连接/生命周期/状态机”用例按 A 类逐类型覆盖，“数据流/参数”用例按 B 类逐模态覆盖。

2.4 数据结构新增字段/接口（0.8.0）

DeviceInfo（getDeviceInfo() 返回）新增字段

字段 含义
EmgMaxSampleRate / EegMaxSampleRate / EcgMaxSampleRate 设备能力上报的最大采样率（0 = 未上报）
ImuChannelCount / ImuSampleRate 聚合 NTF_IMU 流（仅新 EMG 设备；0 = 无聚合流，改用四路独立 ACC/GYRO/EULER/QUAT）
ConnectionIntervalMs / PeripheralLatency / SupervisionTimeoutMs BLE 链路协商参数（仅 bumble dongle 后端；0/-1/0 = 未知）

SensorData 新增接口

  • 元数据：getDeviceMac() / getChannelMask() / isDataValid()（Python 恒为 True）。
  • 整批：channelSamples / startSampleIndex（只读）、clone()（深拷贝）。
  • 单点访问器（ci=通道索引，si=样本索引）：getChannelSample(ci,si) 返回 Sample；getData(ci,si) / getRawData(ci,si) / getImpedance(ci,si) / getSaturation(ci,si) / getSampleIndex(ci,si) / getTimeStampInMs(ci,si) / isLost(ci,si)。

Sample 新增只读字段：rawData / impedance / saturation / channelIndex / timeStampInMs（原有 data / sampleIndex / isLost）。

回调交付形式：onDataCallback 每次交付 list[SensorData]（0.5.0 起为 list，非单个对象）。

3.1 硬件环境

项目 要求

  • pip install --upgrade sensor-sdk（0.8.0；依赖 bleak>=3.0.2、bumble==0.0.233、libusb1、numpy 等）

  • 每次测试结束调用 SensorControllerInstance.terminate()；异常退出（Ctrl+C）需经 terminate() 释放资源。
  • 测试间运动/数据类用例间隔 ≥100ms，避免指令错乱。

4.2 用例设计方法（强制）

每个数值参数用边界值 6 点法；非法输入用等价类无效值 + 错误推测；多参数用判定表；设备生命周期用状态迁移；断连/断电用异常恢复。涉及数值型参数（如 init(packageSampleCount, powerRefreshInterval)、startScan(period_in_ms)、multiStartDataNotification(maxDelayDispersionMs, maxAttempts, timeout)、EEG_SAMPLE_RATE）必须覆盖 6 点边界。

4.3 执行方式划分

  • auto：无需人工/仪器，脚本可判定。
  • semi-auto：需人工触发物理动作（如拔 dongle、移动设备、断电），脚本采集与判定。
  • manual：需仪器或不可逆操作，人工执行并记录。

7. 判定标准与通过率目标

  • 单用例通过标准：expected 全部命中，且无未捕获异常、无内存/句柄泄漏。
  • P0 用例：100% 通过；P1：≥95%；P2：≥90%。
  • 所有数值参数必须通过 6 点边界值分析；所有设备类型必须覆盖连接/数据流用例。
  • 失败用例须保留 SDK 日志（controller/profile log）与 .bin，用于复现。

8. 风险与安全注意事项

  1. 连接/断电/断连用例：执行前确认目标设备无人员接触电极/运动部件；异常注入（拔 dongle、断电）仅允许对测试专用设备执行。
  2. 多设备同步：多台设备同时起流时，确保设备固定、运动范围无人员。
  3. 破坏性/不可逆操作（如复位、改 ID、标定等）不纳入自动化，归入人工并按文档单独评估。
  4. terminate() 必须调用：所有脚本（含异常退出路径）须在 finally 中调用，避免 BLE 子进程/句柄泄漏。
  5. 测试间留足间隔：起流/停流/连接类操作之间 ≥100ms。
  6. 配置项外置：串口/dongle/设备前缀/MAC 等写入独立 config.py，不硬编码。
  7. 后端兼容：bumble（dongle）与 bleak（原生）两后端各跑一遍通信/同步用例。
  8. 回调线程安全：onDataCallback 单线程顺序交付，onStateChanged 同步调用，回调内保持短小或线程安全。
