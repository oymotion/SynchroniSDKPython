2.2 OB6000C 设备画像（EEG 多通道核心）

维度说明
命名/识别广播名前缀 OB；广播名 OB6000C(XXXX)，XXXX 为蓝牙地址后四位（当前目标 6C6B）
核心数据流NTF_EEG（脑电，单位 uV），多通道——通道数由 DeviceInfo.EegChannelCount 上报
核心参数EEG_SAMPLE_RATE，可选值来自 getParam("EEG_SAMPLE_RATE_LIST")（示例 250|500|1000|2000）；若同时具备 EEG 与 ECG，两者采样率绑定同写
关联模态（能力门控）ECG（与 EEG 采样率绑定）、ACC/Gyro/Euler/Quat（四路独立 IMU 流）、PPG/SpO2、BRTH、Impedance、MagAngle——均按 getDeviceInfo() 对应 *ChannelCount>0 运行时判定
聚合 IMUOB6000C 为 EEG 设备，预计 ImuChannelCount==0（无 NTF_IMU 聚合流）；若 >0 则按新 EMG 设备逻辑测
远程控制非 NeuCir 设备，NEUCIR_* 参数不适用
链路参数ConnectionIntervalMs/PeripheralLatency/SupervisionTimeoutMs 仅 bumble dongle 后端上报，0/-1/0 表示未知

关键结论：EEG 多通道 + EEG_SAMPLE_RATE 是 OB6000C 的测试重点；其余模态的“支持与否”本身就是测试结果（能力判定），不能预先写死。

2.3 数据流类型清单（DataType）

NTF_ACC、NTF_GYRO、NTF_EULER_DATA、NTF_QUATERNION、NTF_GEST、NTF_EMG、NTF_MAG_ANGLE_DATA、NTF_EEG、NTF_ECG、NTF_IMPEDANCE、NTF_IMU、NTF_ADS、NTF_BRTH、NTF_IMPEDANCE_EXT、NTF_SPO2、NTF_PPG。

其中 OB6000C 核心关注：NTF_EEG（多通道 uV）；能力门控关注：NTF_ECG、NTF_ACC、NTF_GYRO、NTF_EULER_DATA、NTF_QUATERNION、NTF_PPG、NTF_SPO2、NTF_BRTH、NTF_IMPEDANCE、NTF_MAG_ANGLE_DATA。

3. 测试环境与前置条件

3.1 硬件环境

项目要求
被测设备OB6000C ≥1 台（EEG 多通道）；异步多设备用例（ASYNC-FUNC-011/012）需 ≥2 台
蓝牙接口原生 BLE（bleak 后端）或 USB BLE dongle（bumble 后端，如 10d7:b012/33fa:0012）
测试主机Windows 10/11（本环境）、Linux、macOS（跨平台用例）
电极/佩戴EEG 为接触式电极，测试时需佩戴（电极接触皮肤）以获得有效数据

3.2 软件环境

  • Python 3.10 ~ 3.14
  • pip install --upgrade sensor-sdk（0.9.5；依赖 bleak>=3.0.2、bumble==0.0.233、libusb1、numpy 等）
  • 示例依赖：scipy、matplotlib、PyQt5（可选）

3.3 通用前置条件

  • 蓝牙已开启，或 dongle 已正确绑定驱动（checkSetupDongle() 返回 OK）。
  • 设备已上电、在扫描范围内、广播名符合 OB 前缀。
  • 每次测试结束调用 SensorControllerInstance.terminate()。
  • 起流/停流/连接类操作之间间隔 ≥100ms。
  • 多设备（异步多设备用例）需拔掉 USB BLE dongle 以规避“dongle 半启用状态破坏 bleak 多设备连接”的问题（见 §8）。

4.2 用例设计方法（强制）

每个数值参数用边界值 6 点法；非法输入用等价类无效值 + 错误推测；多参数用判定表；设备生命周期用状态迁移；断连/断电用异常恢复。涉及数值型参数（如 init(packageSampleCount, powerRefreshInterval)、startScan(period_in_ms)、EEG_SAMPLE_RATE）必须覆盖 6 点边界。

4.3 执行方式划分

  • auto：无需人工/仪器，脚本可判定。
  • semi-auto：需人工触发物理动作（如拔 dongle、移动设备、断电），脚本采集与判定。
  • manual：需仪器或不可逆操作，人工执行并记录。

7. 判定标准与通过率目标

  • 单用例通过标准：expected 全部命中，且无未捕获异常、无内存/句柄泄漏。
  • P0 用例：100% 通过；P1：≥95%；P2：≥90%。
  • “能力门控”用例（设备不支持而记录“不适用/不支持”）不纳入失败，但需在结果中明确标注“能力判定：不支持”。
  • 所有数值参数必须通过 6 点边界值分析；EEG 多通道与 EEG_SAMPLE_RATE 必须实测验证。
  • 失败用例须保留 SDK 日志（controller/profile log）与 .bin，用于复现。

8. 风险与安全注意事项

  1. 连接/断电/断连用例：执行前确认目标设备无人员接触电极/运动部件；异常注入仅允许对测试专用设备执行。
  2. 多设备用例（ASYNC-FUNC-011/012）：确保设备固定、运动范围无人员。
  3. dongle 半启用状态：插入 dongle 但后端仍为 bleak 时，会破坏 bleak 多设备连接。bleak 多设备测试前拔掉 dongle。
  4. 异步接口事件循环：asyncio.run() 协程内必须使用异步 BLE API，同步接口会返回 None。
  5. 破坏性/不可逆操作（复位、改 ID、标定等）不纳入自动化，归入人工。
  6. terminate() 必须调用：所有脚本（含异常退出路径）须在 finally 中调用。
  7. 测试间留足间隔：起流/停流/连接类操作之间 ≥100ms。
  8. 后端兼容：bumble 与 bleak 两后端各跑一遍通信用例。
  9. 回调线程安全：onDataCallback 单线程顺序交付，回调内保持短小或线程安全。
