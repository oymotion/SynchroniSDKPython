## 1. 变更详析

### 1.1 `startScan` / `stopScan` 返回 bool（非破坏）

- 1.4.3：`startScan(periodInMs)`、`stopScan()` 均无返回值（返回 `None`）。
- 1.4.4：两者均返回 `bool`——启动/停止成功返回 `True`，失败（如蓝牙未开启）返回 `False`。

**影响：**

- 旧代码 `ctrl.startScan(3000)` / `ctrl.stopScan()` 忽略返回值即可，**向后兼容**。
- 新增能力：可显式断言返回值，`CTRL-FUNC-003` 已补充 `startScan()`/`stopScan()` 均返回 `True` 的断言（`test_ctrl_func_003.py`）。
- 破坏面仅存在于「依赖返回值为 `None`」的代码，仓库内无此类用法。

### 1.2 `startScan` 周期参数校验抛 `ValueError`（行为变化）

- 1.4.4 新增 `_validate_scan_period`，对 `periodInMs` 做显式校验：`≤0`（含 0、负数）、非 `int`、`> 0x7FFFFFFF`（int32 上限）均抛 `ValueError`。
- 1.4.3 及之前：非法周期值行为未定义（可能被原生层接受、返回 `False`、或进程级崩溃 segfault）。

**语义变化：**

| 入参 | 1.4.3 行为 | 1.4.4 行为 |
|---|---|---|
| 合法值（1 / MAX-1 / MAX） | 正常启动扫描 | 不变，返回 bool |
| 非法值（0 / -1 / MAX+1 / 非 int） | 未定义/可能崩溃 | 抛 `ValueError` |

**影响：**

- 边界用例 `CTRL-BND-001` 的判定语义已更新：非法值「被拒绝（抛 `ValueError`）即通过；返回 `True` 判 FAIL」，并移除旧「被拒绝/提示且不崩溃」的含糊表述。对应脚本 `test_ctrl_bnd_001.py`（子进程探针捕获异常）已同步说明。
- 合法值路径不受影响；对非法值的显式抛异常是「防崩溃」的收敛，属正向收紧。

### 1.3 `SensorController.onScanStateChange` 回调（非破坏，新增）

- 类型标注：`Callable[[bool, str], None]`（`sensor_controller.py` L75）。
- 回调签名：`on_scan_state_change(is_scanning: bool, error_msg: str)`；PascalCase 别名 `onScanStateChange`。
- 语义：扫描状态变化时触发——`startScan` 成功进入扫描态收到 `is_scanning=True`；`stopScan` 停止后收到 `is_scanning=False`；蓝牙关闭/错误路径 `is_scanning=False` 且 `error_msg` 可能非空。

**影响：**

- 纯新增可选回调，不注册无影响。
- 新增用例 `CTRL-FUNC-014` → `test_ctrl_func_014.py` 覆盖正向（起/停翻转）+ 错误路径（关闭蓝牙）。

### 1.4 `SensorProfile.isAutoReconnecting` 属性（非破坏，新增）

- `isAutoReconnecting -> bool`（`sensor_profile.py` L388）。
- 语义：自动重连**进行中**返回 `True`，未重连/恢复完成返回 `False`；与 `deviceState` 状态机互补，用于区分「断链」与「重连进行中」。

**影响：**

- 纯新增只读属性，无破坏。
- 新增用例 `DEV-SM-016` → `test_dev_sm_016.py`（semi-auto，断电触发重连窗口内读 `True`，恢复后读 `False`）。

### 1.5 `SensorProfile.onAutoReconnectingStateChange` 回调（非破坏，新增）

- 类型标注：`Callable[["SensorProfile", bool], None]`（`sensor_profile.py` L78）。
- 回调签名：`on_auto_reconnecting_state_change(sensor, is_auto_reconnecting: bool)`；PascalCase 别名 `onAutoReconnectingStateChange`。
- 语义：自动重连状态变化时触发——进入重连收到 `(sensor, True)`，恢复完成收到 `(sensor, False)`；`sensor` 为对应 `SensorProfile` 实例。

**影响：**

- 纯新增可选回调，与 `isAutoReconnecting` 查询互补。
- 新增用例 `DEV-SM-017` → `test_dev_sm_017.py`（semi-auto，断言两次回调 + `sensor` 类型）。

## 3. 分析方法与局限

**证据来源：**

1. `site-packages/sensor/sensor_controller.py`（`startScan`/`stopScan` 签名、`onScanStateChange` L75/L148-177、`_validate_scan_period`、`_c_scan_state`）。
2. `site-packages/sensor/sensor_profile.py`（`onAutoReconnectingStateChange` L78/L364-377、`isAutoReconnecting` L388）。
3. `pyqt_demo.py` 相对 1.4.3 的 diff（确认新增回调/属性/返回值的调用方式）。
4. 手工用例与自动化脚本的同步记录（`Manual Cases/*`、`Automation/Generalized/*`）。

**结论置信度：**

- 1.4.3 → 1.4.4 的 Python 公开接口差异为**高置信度**：变更集中在 `sensor_controller.py` 与 `sensor_profile.py` 两处，均为「新增返回值/新增回调/新增属性 + 参数校验收敛」，无移除、无重命名，破坏性极低。

**局限：**

- 未对 1.4.3 与 1.4.4 两个 wheel 做完整逐文件 diff（本机仅核对了改动点及其上下文），若 1.4.4 另含未在本清单的原生层（`sensor.dll`）行为变化，需另行以 wheel 精确 diff 确认。
- `_validate_scan_period` 的完整边界（如 `bool` 是否视为 `int`、极大非 int 类型的处理）仅在 Python 侧可读校验逻辑确证，最终以实测为准。
