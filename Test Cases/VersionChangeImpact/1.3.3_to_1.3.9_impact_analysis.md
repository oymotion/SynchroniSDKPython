# SDK 1.3.3 → 1.3.9 版本变更影响分析（手工用例）

- 分析日期：2026-10-16
- 目标版本区间：sensor-sdk `1.3.3` → `1.3.9`
- 分析范围：`Test Cases/Manual Cases/` 下 3 台设备（Cerelax Pro / gForceUltra / OB6000C）的手工用例
- 性质：**只分析、不改代码**。本文档给出受影响用例清单与修改建议，供后续统一修订。

---

## 0. 结论摘要

1.3.3 → 1.3.9 区间内，对「手工用例」产生实质影响的是 **一个破坏性变更**（`getBinFileInfo` 返回类型 dict → `BinFileInfo` 对象），加上若干「用例文本过时/笔误」与「版本号显示不一致」问题。逐项列出：

| # | 变更/问题 | 破坏性 | 影响手工用例 | 备注 |
|---|---|---|---|---|
| 1 | `getBinFileInfo()` 返回 `dict` → `BinFileInfo` 对象，字段 snake_case key 变为 PascalCase 属性 | ✅ 破坏性 | BIN-FUNC-002（3 设备） | 1.3.9 引入，本次核心变更 |
| 2 | `getVersion()` 版本号显示不一致（原生 DLL 返回 1.3.8，pip 包为 1.3.9），且手工用例预期写的是 0.9.x | ⚠️ 显示问题 | CTRL-FUNC-012（3 设备） | 非接口变更，属 SDK 发布侧 bug + 用例文本过时 |
| 3 | `multiReplayBinFile(file_paths, sensors, ...)` 的 `sensors` 为必填 | ✅ 笔误 | BIN-FUNC-011（Cerelax Pro）、BIN-FUNC-010（gForceUltra/OB6000C）、BIN-BND-002/003 | 1.3.0 起即如此，手工用例一直未跟上 |
| 4 | `getBinFileInfo(None)` 在 1.3.9 会抛 `AttributeError` | ⚠️ 待验证 | BIN-BND-002（Cerelax Pro） | 边界容错用例，需实测确认 |
| 5 | `DeviceInfo` 新增能力字段、`replayBinFile` 新增参数 | 非破坏性 | （可选增强 MISC-FUNC-008） | 向后兼容，不强制改 |

## 1. 变更点详析

### 1.1 `getBinFileInfo()` 返回类型变更（破坏性，1.3.9 引入）

这是本次区间内**唯一确定性的破坏性变更**。

- 旧（1.3.3 及之前）：返回 `dict`，键为 snake_case。
- 新（1.3.9）：返回 `BinFileInfo` 对象（`sensor.sensor_device.BinFileInfo`），字段为 PascalCase 属性；无效时仍返回 `None`。

字段映射：

| 旧 dict key | 新 `BinFileInfo` 属性 | 类型 |
|---|---|---|
| `device_mac` | `Mac` | str |
| `device_name` | `DeviceName` | str |
| `replay_duration` | `DurationSec` | float |
| `chip_type` | `ChipType` | int |
| `is_universal_stream` | `IsUniversalStream` | bool |
| `feature_map` | `FeatureMap` | int |
| `device_info` | `DeviceInfo` | `DeviceInfo` 对象（旧为 dict） |
| `sensor_datas` | `SensorDatas` | `list[BinSensorDataConfig]`（旧为 list[dict]） |
| （无） | `ConfigVersion` | int（新增） |
| （无） | `IsNewEmg` | bool（新增） |
| （无） | `IsContainQat6` | bool（新增） |
| （无） | `PpgModel` | int（新增） |
| （无） | `NotifyDataFlag` | int（新增） |
| （无） | `Valid` | bool（新增） |
| （无） | `FirstDataTsMs` | int（新增） |
| （无） | `LastDataTsMs` | int（新增） |

> 子结构说明：旧 `device_info`（dict）的 key 与 `DeviceInfo` 对象属性名同源（均为 PascalCase，如 `ModelName`、`EmgChannelCount`、`ImuChannelCount`…），`sensor_datas` 项同理与 `BinSensorDataConfig` 属性同名。因此子字段**只发生 dict→对象 的访问方式变化**（`info["device_info"]["ModelName"]` → `info.DeviceInfo.ModelName`），字段名本身不变。

**影响面**：自动化侧已通过 `common.bin_info_to_dict()` 兼容 shim 消化（不影响手工用例文本）。手工用例 BIN-FUNC-002 的「预期结果」仍按旧 dict 描述，需要修订。

### 1.2 `getVersion()` 版本号显示不一致

- `pip show sensor-sdk` / `sensor.__version__` = `1.3.9`（Python 包元数据）。
- `SensorController.getVersion()` 走原生 `sensor.dll` 的 `sen_controller_get_version`，当前返回 `1.3.8`（DLL 版本字符串未随 Python 包 bump）。
- 这不是脚本/用例能修的，属 **SDK 发布侧未同步**，建议反馈厂商。

**影响面**：手工用例 CTRL-FUNC-012 的「预期结果」写的是 `0.9.6`（Cerelax Pro / OB6000C）或 `0.9.1`（gForceUltra），明显过时，需要更新为「非空版本号（当前 1.3.x）」，并注明「getVersion 可能落后于 pip 包版本」。

### 1.3 `multiReplayBinFile()` 的 `sensors` 为必填（1.3.0 起）

1.3.9 实际签名：

```python
def multiReplayBinFile(self, file_paths, sensors, realtime=True,
                       timeout=None, block=True, timeoutMs=0) -> list
```

- `sensors` **无默认值、必填**，且必须与 `file_paths` 长度一致；长度不匹配或含 `None` 会抛 `ValueError`。
- 自动化脚本 `test_bin_bnd_002.py` 已明确注释「1.3.0 起 sensors 为必填」。
- 手工用例仍写成 `multiReplayBinFile(file_paths, sensors=None, realtime=True)`，属**长期未修正的笔误**（并非 1.3.9 新引入，但当前区间内仍需一并修订）。

### 1.4 `getBinFileInfo(None)` 边界行为（待验证）

1.3.9 的 `getBinFileInfo` 内部直接 `file_path.encode()`，对 `None` 入参会抛 `AttributeError`（对空串 `""` 会以 `b""` 传给 DLL，正常走无效判断返回 `None`）。

手工用例 BIN-BND-002（Cerelax Pro）预期「空串/None/无效路径均返回 None/False 或被拒绝，不崩溃、不抛异常」。`getBinFileInfo(None)` 这一条在 1.3.9 下可能与预期冲突。**需实测确认**，再决定是记 SDK 边界 bug 还是调整用例预期。

### 1.5 非破坏性变更（不影响现有用例通过，可选择性增强）

- `DeviceInfo` 新增能力字段：`EmgMaxSampleRate` / `EegMaxSampleRate` / `EcgMaxSampleRate`、`EmgGain` / `EegGain` / `EcgGain`、`MTUSize` / `IsMTUFine`、`ConnectionIntervalMs` / `PeripheralLatency` / `SupervisionTimeoutMs`、`Backend`、`GestChannelCount` / `GestSampleRate`。
  - 影响：MISC-FUNC-008「DeviceInfo 能力字段完整性」可**补充**校验这些新字段，但现有断言不受影响。
- `replayBinFile()` 新增 `block`、`timeoutMs` 参数（均有默认值，向后兼容）。
  - 影响：BIN-FUNC-004/005 现有 `replayBinFile(path, sensor, realtime=...)` 用法兼容。

## 4. 不在本次区间（1.3.3→1.3.9）但相关历史变更（供参考）

以下变更发生在 **1.3.0**，且手工用例已注明「接口已移除」，本次无需处理，仅列备查：

- `SensorData.channelSamples` 移除 → 改用 `getChannelCount()` / `getSampleCount()` / `getChannelSample()`。
- `SensorData.clear()/reset()`、`to_flatbuffers()/from_flatbuffers()/from_flatbuffers_pooled()` 移除（`SensorData` 只读，仅保留 `clone()`/`as_numpy()`）。
- `Sample.reset()` 及 `Sample.timeStampInMs` 移除（`Sample` 只读）。
- `multiReplayBinFile` 的 `sensors` 改为必填（此点仍反映在本次清单 2.1–2.3，因为用例文本未跟上）。

## 5. 分析方法与局限

**证据来源：**

1. 已安装 SDK 1.3.9 的公开接口（`site-packages/sensor/`：`sensor_controller.py`、`sensor_profile.py`、`sensor_data.py`、`sensor_device.py`、`__init__.py`）。
2. `Python/SynchroniSDKPython/README.md`（接口文档，仍按 1.3.0 编写）。
3. `Test Cases/Manual Cases/`（手工用例，README 标注 SDK 版本 1.3.0）。
4. 本地 `SanityLogs` / `Sample Rate Result` 实测日志（旧版本实测为 1.3.3，当前为 1.3.8/1.3.9）。

**局限：**

- 本机**没有 1.3.3 的包源码**可做精确 diff；1.3.3 → 1.3.9 的确切变更清单是通过「1.3.9 公开接口 vs 1.3.0 文档/手工用例」反推得出。
- 已确认的破坏性变更（`getBinFileInfo` dict → `BinFileInfo`）以 1.3.9 代码 + 运行报错为实锤；其余（`multiReplayBinFile sensors` 必填、`getVersion` 落后）有自动化脚本注释与实测日志佐证，标记为 1.3.0 或发布侧问题。
- 若后续拿到 1.3.3 的 wheel 源码，可对 `getBinFileInfo`、`DeviceInfo`、`DataType` 等做逐字段精确 diff，进一步收紧本清单。
