# SDK 1.3.9 → 1.4.3 公开接口差异分析

- 分析日期：2026-10-30
- 目标版本区间：sensor-sdk `1.3.9` → `1.4.3`
- 分析范围：Python 公开接口（`sensor` 包 `__all__` 导出的类 / 枚举 / 函数，及它们的公开属性与方法）
- 性质：**只分析、不改代码**。本文档在 1.3.9 → 1.4.2 分析基础上，补充 1.4.2 → 1.4.3 增量（依据 README 官方 Changelog + 1.4.2 / 1.4.3 wheel 精确 diff）。

---

## 0. 结论摘要

### 0.1 全区间（1.3.9 → 1.4.3）累计破坏性变更（沿用上版）

1. **`DataType` 枚举重命名 + 新增**：`NTF_MAG_ANGLE_DATA`(0x0D) → `NTF_ANGLE_DATA`(0x0D)，同时新增独立的 `NTF_MAG`(0x3)。
2. **`SensorDataPool` 移除**：`sensor.sensor_data_pool` 模块不再存在，`SensorDataPool` 无法导入。

### 0.2 本次升级（1.4.2 → 1.4.3）差异

README 官方 Changelog 的 1.4.3 仅三条；经 wheel 精确 diff 确认，**Python 公开接口层面实际只有一处破坏性行为变化**，另有一处原生层行为变化：

| # | 变更 | 破坏性 | 影响脚本/用例 | 证据 |
|---|---|---|---|---|
| 8 | `setParam` / `getParam`（sync + async，Controller + Profile）在错误/超时由「返回 `"Error:..."` 字符串」改为「抛 `IOError`」 | ✅ 破坏（对依赖字符串返回值者） | `probe_*` / `triage` 诊断脚本的「支持/不支持」判定 | README bullet #2；Python 源码 diff 确证 |
| 9 | 阻抗流（`NTF_IMPEDANCE`）元数据与时间戳固定 1 Hz（live + replay），与 EXG 采样率解耦 | ⚠️ 行为变化 | `ob3000.py` 头部注释过时（250Hz→1Hz）；其余 spec 已按 1Hz | README bullet #1；`sensor_data.py` 未变，原生 `sensor.dll` 变更 |
| 10 | GUI 示例新增 LSL 输出 / 每通道单位 / 流元数据 | 非破坏 | 无（示例不在 pip wheel 内） | README bullet #3 |
| 11 | `__version__` 1.4.2 → 1.4.3 | 非破坏 | 无 | `__init__.py` |

## 1. 破坏性变更详析（1.3.9 → 1.4.2 累计）

> 本节为 1.3.9 → 1.4.2 已确认的破坏性变更，1.4.3 未回退，仍适用。据 README Changelog，其中 `DataType` 重命名实为 **1.4.1** 引入（见 §4.1）。

### 1.1 `DataType` 枚举：`NTF_MAG_ANGLE_DATA` → `NTF_ANGLE_DATA`（重命名）+ 新增 `NTF_MAG`

- 旧（1.3.9，据 AGENTS.md「九、Python SDK 底层 API 速查」）：`DataType.NTF_MAG_ANGLE_DATA = 0x0D`（磁力计+角度合并为一路流）。
- 新（1.4.x，`sensor/sensor_data.py`）：

  ```python
  class DataType(IntEnum):
      ...
      NTF_MAG = 0x3            # 新增：磁力计独立流
      NTF_EULER_DATA = 0x4
      NTF_QUATERNION = 0x5
      NTF_GEST = 0x07
      NTF_EMG = 0x8
      NTF_ANGLE_DATA = 0x0D    # 原 NTF_MAG_ANGLE_DATA，改名（仅角度）
      ...
  ```

**影响：**

- 旧代码 `DataType.NTF_MAG_ANGLE_DATA` 在 1.4.x 会抛 `AttributeError`（该成员已不存在）。
- 磁力计能力从「`NTF_MAG_ANGLE_DATA`(0x0D) 合并流」拆分为：磁力计 `NTF_MAG`(0x3) + 角度 `NTF_ANGLE_DATA`(0x0D) 两个独立流。若后续要覆盖磁力计能力，需按新枚举与 `DeviceInfo.MagChannelCount` 判定。
- 现有 `device_specs/*.py` 里的 `"NTF_MAG_ANGLE"` 是 **`setParam` 的参数字符串 key**（与 `DataType` 枚举名是两套命名，见 ob6000a.py / ob6000c.py 内注释），**不受本次枚举重命名影响**；但 device_specs 注释中出现的 `NTF_MAG_ANGLE_DATA` 字样（ob6000a.py / ob6000c.py）属过时命名，建议顺手更正。

### 1.2 `SensorDataPool` 移除

- 1.4.2 / 1.4.3 的 `site-packages/sensor/` 目录均仅含：`__init__.py`、`_dll.py`、`_sync.py`、`sensor_controller.py`、`sensor_profile.py`、`sensor_data.py`、`sensor_device.py`、`bin/`、`pyinstaller_hooks/`。
- **无 `sensor_data_pool.py`**，`__init__.py` 的 `__all__` 亦未导出 `SensorDataPool`。

**影响：**

- `from sensor.sensor_data_pool import SensorDataPool` 与 `from sensor import SensorDataPool` 均失败。
- 受影响脚本：`gForceUltra/10_Base_Interface_and_Boundary/test_misc_func_005.py` 与 `OB6000C/10_Base_Interface_and_Boundary/test_misc_func_005.py`（MISC-FUNC-005「SensorData 池化」）。两处均已用 `try/except ImportError` 兜底（`SensorDataPool = None`），脚本不会因导入崩溃，但相关断言应按「模块已移除」语义复核。
- README Changelog 未记录此移除，具体移除版本在 1.3.9 → 1.4.2 之间某版，暂无法精确归属。

## 2. 非破坏性变更（1.3.9 → 1.4.2 累计）

> 说明：以下为 1.4.2 相对「1.3.x 速查（AGENTS.md 第九节）+ 1.3.9 分析文档」的增量。因本机无 1.3.9 包源码，**无法精确区分哪些是 1.4.2 新增、哪些是 1.3.9 已有但旧速查未列**。README Changelog 现可按版本细分（见 §4.1），部分条目已能精确定位到 1.4.0 / 1.4.1。

### 2.1 `DeviceInfo` 新增字段

- 新增：`MagChannelCount`、`MagSampleRate`（磁力计能力，对应新增的 `DataType.NTF_MAG`，1.4.1 引入）。
- 其余字段与 1.3.9 一致（含 1.3.9 已引入的 `EmgMaxSampleRate` / `EmgGain` / `MTUSize` / `GestChannelCount` 等）。

### 2.2 `SensorData` 新增属性与方法

新增**属性**（property，可与既有 `getXxx()` 并用）：

- `deviceMac` / `deviceName` / `dataType` / `lostPackageCount` / `sampleRate` / `channelCount` / `channelMask` / `sampleCount` / `startTimeStamp` / `delay` / `startTimeSec` / `startSampleIndex`

新增**方法**：

- `getDeviceMac()` / `getDeviceName()`
- `getChannelMask()`
- `isChannelEnabled(channelIndex)`
- `getTimeStampInMs(channelIndex, sampleIndex)` —— 由 `sampleIndex / sampleRate` 反推（注意：并非设备发送时钟）
- `getAbsTimeStampInSec(channelIndex, sampleIndex)` —— 读 buffer 内绝对时间戳
- `getSampleIndex(channelIndex, sampleIndex)`
- `getImpedance(channelIndex, sampleIndex)`
- `getSaturation(channelIndex, sampleIndex)`
- `isLost(channelIndex, sampleIndex)`
- `isDataValid(channelIndex=0, sampleIndex=0)`

既有方法 `getDataType/getSampleCount/getSampleRate/getChannelCount/getRawData/getData/getStartTimeStamp/getDelay/getStartTimeSec/as_numpy/clone` 保留。

### 2.3 `SensorController` 新增方法

- 持续扫描：`startScan(periodInMs)` / `stopScan()` / `isScanning`（属性）
- 多设备查询：`getSensors()` / `getConnectedSensors()` / `getConnectedDevices()`
- 回放控制：`pauseBinReplay(sensor)` / `resumeBinReplay(sensor)` / `stopBinReplay(sensor)`
- 其它：`onSuspend()`、`checkSetupDongle()`、`getBLEBackendName()`
- 异步（`async` 协程）：`asyncScan` / `asyncMultiStartDataNotification` / `asyncMultiStopDataNotification` / `asyncParseBinToCsv` / `asyncCheckSetupDongle` / `asyncGetParam` / `asyncSetParam`

既有 `terminate / requireSensor / getSensor / multiStartDataNotification / multiStopDataNotification / log / getBinFileInfo / replayBinFile / multiReplayBinFile / parseBinToCsv / getVersion / getParam / setParam / setDebugEnabled / setLogPath / scan` 保留。

### 2.4 `SensorProfile` 新增属性 / 方法 / 回调

- 属性：`deviceState`（返回 `DeviceStateEx` 枚举）、`isReady`、`hasInited`、`isDataTransfering`、`autoReconnect`、`BLEDevice`
- 方法：`getDeviceInfo()`（缓存读取）、`fetchDeviceInfo(timeoutInMS=0)`（主动拉取）
- 回调（snake_case 与 PascalCase 双风格并存）：
  - 新增：`on_state_change` / `onStateChanged`、`on_device_info_update` / `onDeviceInfoUpdate`、`on_data_transfer_state_change` / `onDataTransferStateChange`、`onAutoReconnect`
  - 既有：`onDataCallback` / `onErrorCallback` / `onPowerChanged` 等保留
- 方法签名扩展（新增默认参数，向后兼容）：
  - `setParam(key, value, timeoutInMS=0)`、`getParam(key, timeoutInMS=0)`、`init(packageSampleCount, powerRefreshInterval, timeoutInMS=0)`
- 异步（`async` 协程）：`asyncConnect` / `asyncDisconnect` / `asyncInit` / `asyncStartDataNotification` / `asyncStopDataNotification` / `asyncGetBatteryLevel` / `asyncSetParam` / `asyncGetParam` / `asyncFetchDeviceInfo`

既有 `connect / disconnect / init / startDataNotification / stopDataNotification / setParam / getParam / getBatteryLevel / log` 保留。

### 2.5 其它公开导出（`__init__.py`）

1.4.2 / 1.4.3 的 `sensor.__all__` 一致：

```
SensorController, SensorControllerInstance, SensorProfile, BLEDevice, DeviceInfo,
DeviceStateEx, BinFileInfo, BinSensorDataConfig, DataType, Sample, SensorData,
dll_path, capi_version, submit, __version__
```

- `DeviceStateEx`（Enum：`Disconnected=0 / Connecting=1 / Connected=2 / Ready=3 / Disconnecting=4 / Invalid=5`）为状态机公开枚举，`SensorProfile.deviceState` 返回该类型。
- `submit(fn, *args, **kwargs)`：后台线程执行器（`sensor._sync.submit`），返回 `concurrent.futures.Future`。
- `capi_version()`：返回原生 CAPI 版本号。
- `SensorControllerInstance`：单例实例别名（`SensorController.__new__` 实现单例）。

## 3. 需确认项（1.3.9 → 1.4.2 累计）

### 3.1 `SensorData.getChannelSample()` 签名疑似变化

- AGENTS.md 第九节速查记为 `getChannelSample(ci)`（单参数，取某通道样本）。
- 1.4.2 源码为 `getChannelSample(channelIndex, sampleIndex) -> Sample`（双参数，取单个样本点）。1.4.3 未变。

若 1.3.9 确为单参数签名，则属破坏性变更。**但现有自动化脚本均未调用 `getChannelSample`**，实际影响为 0。建议在拿到 1.3.9 wheel 后对 `getChannelSample` 做精确确认。

### 3.2 `SensorProfile.init()` 参数顺序

- 1.4.2 / 1.4.3：`init(packageSampleCount, powerRefreshInterval, timeoutInMS=0)`。
- 现有脚本（1.3.8 实测可跑）均用两参 `init(config.PACKAGE_SAMPLE_COUNT, config.POWER_REFRESH_INTERVAL_MS)`，与 1.4.3 兼容。
- 注意区分：AGENTS.md 中 `init(packageSampleCount, timeoutMs, ...)` 是 **Android 侧**注释，非 Python 侧签名，勿混淆。

### 3.3 「新增」清单的版本精确性

本机无 1.3.9 包源码，§2 的「新增」清单是「1.4.2 源码 vs 1.3.x 速查/文档」的增量；其中部分接口（如 `getBLEBackendName`、`DeviceStateEx`、`hasInited`、`submit`、两参 `init`）在 1.3.8 实测输出中已出现，**可能并非 1.4.2 首次引入**。README Changelog 已能对部分条目按版本归属（见 §4.1），但 1.3.9 单点精确 diff 仍需 1.3.9 wheel。

## 4. 1.4.2 → 1.4.3 增量差异（本次）

### 4.1 版本归属更正（依据 README Changelog）

README 现已提供按版本细分的官方 Changelog，据此对上版「累计对比」中的若干条目做归属更正：

| 变更 | 实际引入版本 | 上版归属 |
|---|---|---|
| `NTF_MAG` 新增 + `MAG_ANGLE`→`ANGLE` 改名 | **1.4.1** | 误归 1.4.2 |
| 聚合 `NTF_IMU`、参数方法开始抛 `IOError` | 1.4.0 | 未细分 |
| 自动重连增强、`onAutoReconnect` 异步 `answer` | 1.4.2 | 未细分 |
| `SensorDataPool` 移除 | README 未记录，1.3.9→1.4.2 之间 | 误归 1.4.2 |

### 4.2 变更 A：`setParam` / `getParam` 错误语义改为抛 `IOError`（破坏性）

README 1.4.3 bullet #2「Added parameter capability checks and clearer parameter errors」的 Python 侧可确证部分。

**源码 diff（1.4.2 → 1.4.3）：**

- `sensor_profile.py` 新增 `_check_param_result`：

  ```python
  def _check_param_result(result: str) -> str:
      if result.startswith("Error") or result.startswith("ERROR:"):
          raise IOError(result)
      return result
  ```

- 同步 `setParam` / `getParam`（`SensorProfile` 与 `SensorController` 各一处）：`FuturesTimeoutError` 由 `return "Error: Timeout"` 改为 `raise IOError("Error: Timeout")`。
- 异步 `asyncSetParam` / `asyncGetParam`：`return await asyncio.wait_for(...)` 改为 `return _check_param_result(result)`。

**语义变化（1.4.2 → 1.4.3）：**

| 场景 | 1.4.2 行为 | 1.4.3 行为 |
|---|---|---|
| 参数错误（不支持/非法值） | 返回 `"Error: ..."` 字符串 | 抛 `IOError("Error: ...")` |
| 超时 | 返回 `"Error: Timeout"` 字符串 | 抛 `IOError("Error: Timeout")` |
| 成功 | 返回 `"OK"` 或有效值 | 不变 |

**影响：** 任何「以 `getParam` / `setParam` 返回字符串是否 `Error` 开头来判断能力支持」的代码都会受影响——它们在 1.4.3 会改为接到 `IOError`。已在仓库内核对：

- 核心用例（`e2e_smoke` / `test_measure_sample_rate` / `longevity` / `stress`）对 `getParam` / `setParam` 基本已 `try/except` 兜底，或只对**受支持的有效 key** 调用（返回 `"OK"` 不抛），**不会崩溃**。
- 受影响的是主动探测「不支持 key」的**诊断脚本**（`probe_*` / `triage`），详见 §5。

### 4.3 变更 B：阻抗流元数据 / 时间戳固定 1 Hz（行为变化，原生层）

README 1.4.3 bullet #1。

- `sensor_data.py` / `sensor_device.py` **未变**，Python 包装层无公开 API 变化；改动在原生 `sensor.dll`（2,212,352 → 2,296,320 字节）。
- 语义：`NTF_IMPEDANCE` 批次的 `getSampleRate()` 与 `getTimeStampInMs()` / `getAbsTimeStampInSec()` 时间戳统一按 1 Hz，live 与 replay 一致，不再跟随 EXG（EEG/ECG）采样率。
- 仓库内多数 `device_specs/*.py` 已把阻抗标为「固定 1Hz」（gforce_ultra / gforce_max / cerelax_pro / ob6000a / ob6000c），`test_measure_sample_rate.py` 亦按「固定 1Hz 跳过 setParam」处理，**不受影响**。
- 例外：`device_specs/ob3000.py` 头部注释（L14）仍记录「NTF_IMPEDANCE(ch=24, rate~250Hz)」（旧行为）；但其 `sample_rates.IMPEDANCE.rates=["1"]` 已按 1Hz，属**注释过时**，建议更正注释。

### 4.4 变更 C：GUI 示例（非 SDK API，无影响）

README 1.4.3 bullet #3：GUI 示例新增可选 LSL 输出、每通道单位、流元数据；自动重连保留各 outlet 的 `source_id` / `uid` / `session_id`。示例不在 pip wheel 的 `sensor/` 包内，对 SDK 公开 API 无影响。

## 6. 分析方法与局限

**证据来源：**

1. **1.4.2 与 1.4.3 两个 wheel 的精确源码 diff**（`sensor/` 包：`__init__.py`、`sensor_controller.py`、`sensor_profile.py`、`sensor_data.py`、`sensor_device.py`、`_sync.py`、`_dll.py`），以及 `sensor.dll` 二进制差异。
2. `README.md` 官方 Changelog（1.4.0 / 1.4.1 / 1.4.2 / 1.4.3 逐版记录）。
3. 既有分析文档 `1.3.3_to_1.3.9_impact_analysis.md`（记录 1.3.9 的 `getBinFileInfo` / `multiReplayBinFile` / `DeviceInfo` 等接口）。
4. `AGENTS.md` 第九节「Python SDK 底层 API 速查」（1.3.x 的 `DataType` / `SensorData` 记录）。
5. 现有自动化脚本（`Automation/` 下各设备脚本及其 `getParam` / `setParam` 调用与错误处理方式）。

**结论置信度：**

- **1.4.2 → 1.4.3 的 Python 公开接口差异为高置信度**：两 wheel 源码 diff 显示 Python 层仅 `__init__.py`（版本号）、`sensor_controller.py`、`sensor_profile.py` 三处改动，其余 `sensor_data.py` / `sensor_device.py` / `_sync.py` / `_dll.py` 完全相同。唯一公开 API 行为变化是参数方法错误语义（§4.2）。
- **阻抗 1Hz（§4.3）为原生层变更**：`sensor_data.py` 未变、`sensor.dll` 二进制变化 + README 声明为据，Python 侧无法进一步确证内部实现。

**局限：**

- 本机仍**无 1.3.9 包源码**，1.3.9 → 1.4.2 的「新增」清单精度仍受局限（§3.3）；但 1.4.2 → 1.4.3 已用两 wheel 做精确 diff，不受此局限。
- README Changelog 未记录 `SensorDataPool` 移除，该条的具体移除版本仍待确认。
- 参数「能力校验」的完整实现（值校验、`*_SAMPLE_RATE_LIST` 拒绝逻辑）主要在原生 DLL，Python 侧仅能确证「错误 → 抛 IOError」这一层。
