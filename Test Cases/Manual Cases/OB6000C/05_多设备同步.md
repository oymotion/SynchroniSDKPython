# OB6000C 多设备同步用例（MULTI-*）

> 本组需 **≥2 台设备**。OB6000C 可与同型号或其他型号（如 OYWW1100）混合组合同步。若只有 1 台，整体"跳过（缺设备）"，不判失败。
> 签名（0.9.1）：`multiStartDataNotification(sensors, timeout=30.0, maxDelayDispersionMs=5, maxAttempts=3)`；`multiStopDataNotification(sensors, timeout=10.0)`。

### MULTI-FUNC-001 两台同时起流
- **测试目的**：验证多设备同步起流。
- **流程与逻辑**：连接 init 两台，`multiStartDataNotification([s1,s2])`，检查返回 `{mac: bool}` 与两台上流。
- **预期结果**：两台均起流。
- **有效性说明**：同步起流核心能力。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：失败，问题 7124

### MULTI-FUNC-002 两台同时停流
- **测试目的**：验证同步停流。
- **流程与逻辑**：`multiStopDataNotification([s1,s2])` 后检查两台上流状态。
- **预期结果**：两台均停流。
- **有效性说明**：同步停流。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：失败，问题 7124

### MULTI-FUNC-003 某台未 Ready 不影响其余起流
- **测试目的**：验证部分失败不影响整体。
- **流程与逻辑**：一台 Ready，另一台未 init，`multiStart`。
- **预期结果**：Ready 台起流，未 Ready 台失败，其余不受影响。
- **有效性说明**：容错。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：通过

### MULTI-FUNC-004 首包时差 ≤ maxDelayDispersionMs
- **测试目的**：验证同步对齐质量。
- **流程与逻辑**：用默认参数 `multiStart`，统计两台首包 `startTimeStamp` 差；超差应自动停流重试至 `maxAttempts`。
- **预期结果**：时差 ≤ 默认 5ms（或重试后仍超差则明确失败）。
- **有效性说明**：同步精度指标。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：失败，问题 7124

### MULTI-FUNC-005 maxDelayDispersionMs=-1 跳过时差校验

- **流程与逻辑**：`multiStart(..., maxDelayDispersionMs=-1)`。
- **预期结果**：只要求首包到达，不校验时差。
- **有效性说明**：参数语义正确。
- **可自动化**：auto
