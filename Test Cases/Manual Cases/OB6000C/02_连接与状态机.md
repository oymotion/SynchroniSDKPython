# OB6000C 连接与状态机用例（DEV-SM-*）

> 下列用例均针对 OB6000C 单台执行。

### DEV-SM-001 connect 成功，状态迁移 Disconnected→Connecting→Connected→Ready
- **优先级**：P0
- **测试目的**：验证连接成功与状态迁移序列。
- **流程与逻辑**：注册 `onStateChanged`，`requireSensor` 后 `connect()`，记录每次状态变化。
- **预期结果**：返回 True，按 `Disconnected→Connecting→Connected→Ready` 迁移，最终 `deviceState==Ready`、`isReady==True`。
- **有效性说明**：连接是后续操作前提；迁移顺序错误会导致指令在错误状态下发送。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：通过

### DEV-SM-002 connect 失败返回 False 并回调原因
- **优先级**：P1
- **测试目的**：验证连接失败路径。
- **流程与逻辑**：对已关机/超出范围的设备 `connect()`，观察返回与 `onErrorCallback`。
- **预期结果**：返回 False，`onErrorCallback` 收到原因。
- **有效性说明**：失败可观测、不静默。
- **可自动化**：semi-auto
- **人工介入**：人工关闭设备电源或移出范围。
- **测试结果**：失败 问题 7067 未修复

### DEV-SM-015 disconnect 后重新 scan 可再次发现设备
- **优先级**：P1
- **测试目的**：验证主动断开后，同一台设备可被再次扫描发现。
- **流程与逻辑**：scan 匹配目标设备并记录 MAC → requireSensor → connect 到 Ready → disconnect 到 Disconnected → 重新 scan（带重试，按 MAC 精确匹配同一台设备）。
- **预期结果**：断开后重新 scan 的结果包含同一台设备（MAC 一致）。
- **有效性说明**：若断开后 scan 找不到该设备（被 SDK 当作「已连接/已知」而过滤），会影响重连与多设备管理，属缺陷。
- **可自动化**：auto
- **人工介入**：无（设备上电在范围内为运行前置）
- **测试结果**：待测试
