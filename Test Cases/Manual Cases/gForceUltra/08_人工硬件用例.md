# gForceUltra 人工硬件用例（HW-MAN-*）

> 本文件为需要人工/仪器介入的硬件相关用例。
> HW-MAN-004（24h 老化）、HW-MAN-005（高低温）超出 SDK 软件测试范围，归硬件/可靠性团队，不在此展开。

### HW-MAN-001 BLE 链路 RSSI/连接稳定性人工验证
- **测试目的**：验证真实环境 BLE 链路稳定性。
- **流程与逻辑**：在不同距离/遮挡下观察 RSSI 变化与断连情况。
- **预期结果**：有效范围内稳定，超出范围按预期断连并可恢复。
- **有效性说明**：真实射频环境验证。
- **可自动化**：manual
- **人工介入**：移动设备、改变距离/遮挡，记录现象。
- **测试结果**：跳过，不在测试sdk范围

### HW-MAN-006 运行中关闭/打开电脑蓝牙，设备能否继续工作
- **测试目的**：验证电脑侧蓝牙开关切换后，已连接的 gForceUltra 能否继续工作（继续出数据 / 恢复连接）。
- **流程与逻辑**：
  1. 连接 gForceUltra → init → 起流，确认数据正常到达。
  2. 关闭电脑蓝牙，观察 `isEnable`、`deviceState`、`isDataTransfering`、数据是否中断、是否触发错误/断开回调。
  3. 重新打开电脑蓝牙，观察 SDK 是否自动恢复连接与数据，或需重新 scan/connect。
- **预期结果**：关闭蓝牙时 SDK 能感知（`isEnable==False` 或收到关闭回调），已有连接按预期断连/报错而不崩溃；重新打开后能恢复，设备继续工作（重新出数据）。
- **有效性说明**：验证电脑蓝牙开关切换下 SDK 的恢复能力，与 CTRL-FUNC-001/002（问题 7060/7061）相关联。
- **可自动化**：semi-auto
- **人工介入**：运行中人工关闭/打开电脑蓝牙。
- **测试结果**：待测试

### HW-MAN-007 运行中热插拔 dongle，设备能否继续工作
- **测试目的**：验证 dongle 后端下，连接建立后拔掉 dongle 再插回，设备能否继续工作（SDK 是否报错/断连/自动恢复）。
- **流程与逻辑**：
  1. dongle 后端连接 gForceUltra → init → 起流，确认数据正常到达。
  2. 运行中拔掉 dongle，观察 `deviceState`、`isDataTransfering`、数据中断、是否抛异常或崩溃。
  3. 重新插入 dongle，观察 SDK 是否恢复，能否重新扫描/连接/起流。
- **预期结果**：拔掉 dongle 时 SDK 有明确报错或断连（不崩溃、不静默）；插回后能恢复（或经重新 scan/connect 后恢复），设备继续工作。
- **有效性说明**：验证 dongle 热插拔的容错与恢复，覆盖「连接后热插拔」这一空白（区别于 HW-MAN-002 的引导绑定）。
- **可自动化**：semi-auto
- **人工介入**：运行中拔插 dongle。
- **测试结果**：待测试
