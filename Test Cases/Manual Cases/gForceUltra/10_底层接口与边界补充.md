- **流程与逻辑**：未注册时读 `hasDeviceFoundCallback`；注册 `onDeviceFoundCallback` 后再读；清空后再读。
- **预期结果**：未注册 False，注册后 True，清空后 False。
- **有效性说明**：回调注册状态可查询。
- **可自动化**：auto

- **有效性说明**：能力字段是数据流/参数用例的判定依据，必须可靠。

- **测试结果**：通过

### MISC-FUNC-009 submit 后台线程执行器（返回值/线程身份/异常/串行）
- **测试目的**：验证公开 API `submit(fn, *args, **kwargs)` 的线程调度语义。
- **流程与逻辑**：`submit` 纯函数返回 `Future`，`result(timeout)` 取回返回值；验证 `fn` 在后台线程（`sensor-runner`）执行且非调用方线程；验证 `submit` 调用本身立即返回（`fn` 内 sleep 时不阻塞调用方）；`submit` 抛异常函数验证异常经 `Future` 传回；`submit` 多个任务验证单线程串行执行。
- **预期结果**：返回值正确；`fn` 在线程 `sensor-runner` 执行且非调用方线程；`submit` 调用非阻塞；异常经 `Future` 正确传回；任务按提交顺序串行完成。
- **有效性说明**：`submit` 是 SDK 1.3.3 `__all__` 中导出的公开 API，demo 用它后台执行阻塞式 connect/disconnect，当前测试零覆盖，补上。
- **可自动化**：auto（无需设备）
- **人工介入**：无
- **测试结果**：通过

### MISC-FUNC-010 submit 执行阻塞式连接/断开（官方用法）
- **测试目的**：验证 `submit` 包装阻塞式 SDK 调用的官方用法（不冻结调用方线程）。
- **流程与逻辑**：`requireSensor` 后 `fut = submit(sensor.connect)`，断言提交立即返回；`fut.result(timeout)` 取回 `True` 且 `deviceState==Ready`；再 `fut = submit(sensor.disconnect)`，取回 `True` 且 `deviceState==Disconnected`。
- **预期结果**：`submit(connect/disconnect)` 提交不阻塞调用方；连接/断开结果正确、状态迁移正确，与同步接口一致。
- **有效性说明**：demo 官方用法（避免 UI 线程冻结），验证 submit 与阻塞式 BLE 接口的配合。
- **可自动化**：auto（需待测设备上电在范围内）
- **人工介入**：无
- **测试结果**：通过
