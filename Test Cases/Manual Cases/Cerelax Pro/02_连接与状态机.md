# Cerelax 连接与状态机用例（DEV-SM-*）

> 下列用例均针对 Cerelax 单台执行。

### DEV-SM-001 connect 成功，状态迁移 Disconnected→Connecting→Connected→Ready
- **优先级**：P0
- **测试目的**：验证连接成功与状态迁移序列。
- **流程与逻辑**：注册 `onStateChanged`，`requireSensor` 后 `connect()`，记录每次状态变化。
- **预期结果**：返回 True，按 `Disconnected→Connecting→Connected→Ready` 迁移，最终 `deviceState==Ready`、`isReady==True`。
- **有效性说明**：连接是后续操作前提；迁移顺序错误会导致指令在错误状态下发送。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### DEV-SM-017 BLE MTU 协商前后数据分包正确
- **优先级**：P1
- **测试目的**：验证 MTU 协商对数据分包的影响（§七 BLE 专项）。
- **流程与逻辑**：连接 init 起流后，从 profile log 或 bin 观察协商前后的 MTU 值；起流大数据包（如多通道 EEG）验证分包正确、无丢帧、`getLostPackageCount` 不异常增长。
- **预期结果**：协商前后 MTU 值被记录；大数据包按协商后 MTU 正确分包，采样率/丢包率正常（允许容差，来源：实测标定）。
- **有效性说明**：MTU 过小会导致分包异常/丢包，是 BLE 高频问题点。
- **可自动化**：semi-auto
- **人工介入**：无（MTU 由链路自动协商，仅需观察 log/bin）
- **测试结果**：待测试

### DEV-SM-018 配对/bond 信息持久与免配对重连
- **优先级**：P1
- **测试目的**：验证已配对设备重连是否免配对、bond 信息是否持久（§七 BLE 专项）。
- **流程与逻辑**：首次连接完成配对/bond → 断开 → 再次 `connect()`，观察是否免配对直接重连成功；重启 SDK 进程后重连，确认 bond 信息持久。
- **预期结果**：已配对设备再次连接免配对成功；bond 信息在重启后仍持久（若 SDK 不管理 bond，则记录"SDK 不持久化 bond，由 OS 管理"，不判失败）。
- **有效性说明**：bond 丢失会导致每次重连重新配对，影响体验与稳定性。
- **可自动化**：semi-auto
- **人工介入**：首次配对时可能需在【电脑】确认配对弹窗。
- **测试结果**：待测试

### DEV-SM-020 disconnect 后重新 scan 可再次发现设备
- **优先级**：P1
- **测试目的**：验证主动断开后，同一台设备可被再次扫描发现。
- **流程与逻辑**：scan 匹配目标设备并记录 MAC → requireSensor → connect 到 Ready → disconnect 到 Disconnected → 重新 scan（带重试，按 MAC 精确匹配同一台设备）。
- **预期结果**：断开后重新 scan 的结果包含同一台设备（MAC 一致）。
- **有效性说明**：若断开后 scan 找不到该设备（被 SDK 当作「已连接/已知」而过滤），会影响重连与多设备管理，属缺陷。
- **可自动化**：auto
- **人工介入**：无（设备上电在范围内为运行前置）
- **测试结果**：待测试
