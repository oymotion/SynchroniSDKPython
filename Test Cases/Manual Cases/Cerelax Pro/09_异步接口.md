# Cerelax 异步接口用例（ASYNC-*）

> 覆盖 async 变体接口，补齐同步用例的覆盖缺口。
> 说明：所有 async 方法需在 asyncio 事件循环中 `await` 调用（可用 `asyncio.run(...)` 包裹）。
> 签名与同步版本一致，仅返回可等待对象；`asyncMulti*` 需 ≥2 台，缺设备则"跳过"。

### ASYNC-FUNC-010 async/sync 混用行为明确（asyncio 内同步接口返回 None）
- **优先级**：P0
- **测试目的**：验证 async/sync 混用的边界行为，避免误用导致状态错乱。
- **流程与逻辑**：在 `asyncio.run()` 协程内，先 `asyncConnect` 后用同步 `connect()/init()/disconnect()`，观察返回值与 `deviceState`；再在协程外用同步接口、协程内用异步接口各跑一遍完整流程，核对状态迁移。
- **预期结果**：已知 SDK 在运行中的事件循环里调用同步 BLE 接口会返回 `None`（事件循环冲突），`deviceState` 可能停在 `Disconnected`；纯 async（协程内）与纯 sync（协程外）各自状态迁移正确。用例如实记录该限制，不判为"无冲突"。
- **有效性说明**：明确 async/sync 不可在事件循环内混用，防止误用；纯 async 与纯 sync 路径均需各自验证正确。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试
