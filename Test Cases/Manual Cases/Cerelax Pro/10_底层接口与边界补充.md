# Cerelax 底层接口与边界补充用例（MISC-*）

> 补齐覆盖率审计中未覆盖的接口：`hasDeviceFoundCallback`、`SensorData` 序列化/复用接口、`Sample.reset`、`DeviceStateEx.Invalid`、`DeviceInfo` 能力字段。
> 底层序列化接口的准确签名待实际编码时确认，本文件先列用例不遗漏。

### MISC-FUNC-001 hasDeviceFoundCallback 查询
- **优先级**：P2
- **测试目的**：验证"是否已注册发现回调"查询。
- **流程与逻辑**：未注册时读 `hasDeviceFoundCallback`；注册 `onDeviceFoundCallback` 后再读；清空后再读。
- **预期结果**：未注册 False，注册后 True，清空后 False。
- **有效性说明**：回调注册状态可查询。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### MISC-FUNC-007 DeviceStateEx.Invalid 状态（可能不可达）
- **优先级**：P2
- **测试目的**：确认 `DeviceStateEx.Invalid` 是否有真实触发路径，避免留一个测不出结果的用例。
- **流程与逻辑**：先通过源码/README 确认 `Invalid` 是否可达；若可达，构造对应异常场景（如设备信息缺失、异常初始化后）观察是否进入 `Invalid`，并确认 SDK 不崩溃、可断开恢复；若不可达，记录"不可达，不适用"。
- **预期结果**：可达则异常场景下状态可落入 `Invalid` 且可恢复；不可达则标记"不适用"，不判失败。
- **有效性说明**：补齐状态机唯一未覆盖的枚举值；若 SDK 未实现该状态的任何触发路径，则不强行制造。
- **可自动化**：semi-auto
- **人工介入**：人工确认触发路径是否可达。
- **测试结果**：待测试

### MISC-FUNC-008 DeviceInfo 能力字段完整性
- **优先级**：P1
- **测试目的**：验证 `getDeviceInfo()` 返回的能力字段完整且合法。
- **流程与逻辑**：Ready + init 后调 `getDeviceInfo()`，逐一读取 `ModelName`、各模态 `ChannelCount`/`SampleRate`（Eeg/Emg/Ecg/Acc/Gyro/Euler/Quat/Imu/MagAngle/Impe/Ppg/Spo2/Brth），断言字段存在且值 `≥0`。
- **预期结果**：字段齐全，`≥0`；Cerelax 的 EEG 类字段 `>0`（`EegChannelCount==2`）、PPG/IMU/Impedance 类字段 `>0`，EMG/ECG 类为 0。
- **有效性说明**：能力字段是数据流/参数用例的判定依据，必须可靠。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试
