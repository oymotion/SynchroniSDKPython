# Cerelax 电量/日志/调试用例（BATT-* / LOG-*）

## 电量（BATT-*）

### BATT-FUNC-001 getBatteryLevel 返回 0~100（或 -1）
- **测试目的**：验证电量读取。
- **流程与逻辑**：Ready 后调 `getBatteryLevel()`。
- **预期结果**：返回 0~100；无有效读数返回 -1（不判失败，仅记录）。
- **有效性说明**：电量接口可用。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### BATT-FUNC-002 onPowerChanged 上报 0~100，±2% 滞回，不报 -1
- **测试目的**：验证电量回调。
- **流程与逻辑**：注册 `onPowerChanged`，观察上报值（可改变功耗/等待电量变化）。
- **预期结果**：上报 0~100，1% 抖动被过滤，不报 -1。
- **有效性说明**：回调稳定性。
- **可自动化**：semi-auto
- **人工介入**：人工制造电量变化或长时间观察。
- **测试结果**：待测试

### BATT-FUNC-003 powerRefreshInterval 决定上报周期
- **测试目的**：验证刷新周期。
- **流程与逻辑**：设不同 `powerRefreshInterval`，统计 `onPowerChanged` 周期。
- **预期结果**：周期与设置一致。
- **有效性说明**：周期参数生效。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### BATT-FUNC-004 startDataNotification 起流期间 onPowerChanged 持续回调
- **测试目的**：验证起流后 `onPowerChanged` 不会停止回调（针对"startDataNotification 一段时间后 onPowerChanged 停止不再调用"的失效模式）。
- **流程与逻辑**：
  1. 连接 → 到达 `Ready` → `init(packageSampleCount, powerRefreshInterval)`（`powerRefreshInterval` 建议设较小值如 1000ms，便于短时间观察足够多次回调）。
  2. 注册 `onPowerChanged`，记录每次回调到达的时间戳（不关注电量值是否变化）。
  3. `startDataNotification()` 起流（如 `NTF_EEG`）。
  4. 起流后持续观察一段时间（建议 ≥10 分钟），统计相邻回调间隔。
- **预期结果**：起流期间 `onPowerChanged` 按 `powerRefreshInterval` 周期持续到达；观察窗口内任意相邻回调间隔均 ≤ 5×`powerRefreshInterval`（5 倍为线程调度/系统抖动的容错上限），且直到窗口结束仍无静默。
- **有效性说明**：覆盖"起流后电量回调停止"的失效模式；判定基于"回调事件是否持续到达"，不受 ±2% 滞回导致电量值长时间不变的影响。
- **可自动化**：auto（起流后无需人工动作）
- **人工介入**：无
- **测试结果**：待测试
